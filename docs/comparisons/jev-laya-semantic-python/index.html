Decision models and Python integration

Jev vs Laya vs JevLang vs Semantic Python

These projects overlap around typed, probabilistic decisions, but they are not interchangeable. Jev and Laya are decision engines. JevLang and Semantic Python are programming interfaces with different syntax, backend, testing, and runtime choices.

See every difference Semantic Python on PyPI

The short answer

Hosted model and API

Jev

TypeSafe's System One model accepts state plus typed questions and returns probabilistic, structured decisions through a hosted API.

Open-weights decision engine

Laya

A local decision engine for choice, score, and yes/no noul questions, with Python, CLI, and service interfaces.

Python value layer

Semantic Python

A standard-Python library that makes selected values semantic and preserves each Boolean judgment as an inspectable Decision.

JevLang is a fourth piece: a Python source extension that introduces ~ and jev/case syntax and rewrites .jev files to calls against Jev. It is included below because it is the closest syntax-level comparison to Semantic Python.

Using Laya through Semantic Python

Laya supplies local inference; Semantic Python supplies the value boundary, Python operator behavior, decision policy, caching, provenance, and replay. 

python -m pip install "semantic-python[laya]"
from semantic_python import LayaBackend, Semantic, configure

configure(
    backend=LayaBackend(),
    true_threshold=0.85,
    false_threshold=0.15,
    uncertainty="raise",
)

ticket = Semantic("I was charged twice and need a refund")
decision = ticket == "the customer has a billing problem"

if decision:
    route_to_billing()

print(decision.probability, decision.backend, decision.model)

The first Laya prediction may download a checkpoint and initialize a substantial local model stack. Validate quality, latency, memory, and negation behavior on representative data before production use.

Which should you choose?

Choose Jev when

You want TypeSafe's hosted System One model and will build directly against its typed HTTP API.

Choose Laya when

You want an open-weights decision engine on local or self-hosted infrastructure and are comfortable managing its model runtime.

Choose Semantic Python when

You want explicit semantic values in standard Python, backend choice, inspectable uncertainty, caching, replay, and deterministic offline application tests.

Frequently asked questions

Is Semantic Python a Jev replacement?

No. Jev is a model/API; Semantic Python is a Python value layer. A future Jev adapter is roadmap research, not a current integration.

Does Semantic Python replace Laya?

No. Laya can provide the inference behind Semantic Python. The two projects operate at different layers and can be used together.

What is the closest JevLang equivalent?

x ~ "question" in JevLang is closest in intent to Semantic(x) == "proposition", but Semantic Python uses ordinary .py syntax, an explicit wrapper, and a backend-neutral decision protocol.

Does Semantic Python change normal string equality?

No. "done" == "the user wants to stop" remains ordinary deterministic Python. Only Semantic("done") crosses the model-backed boundary.

Can Semantic Python work without a network?

Yes. FakeBackend is entirely offline, and Laya inference can run locally after its model artifacts are available. The OpenAI backend sends the complete wrapped state and proposition to a hosted service.

Are model probabilities facts?

No. They are estimates that require evaluation on the intended domain. Consequential actions need conservative thresholds and an explicit review or fallback path.
